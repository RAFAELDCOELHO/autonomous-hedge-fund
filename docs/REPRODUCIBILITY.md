# BrazilBench reproducibility manifest (P0.2)

Auditable map of **seeds, prompts, JSONL schemas, model versions, and
artifact paths** for the **$0 reproduce path**. This document does not run
models; it records what is committed on `main`, what `make reproduce` /
`make reliability` regenerate, and what still lives only on open PR
branches.

Environment lock for classical offline targets: `.python-version`
(**3.12.13**) + `uv.lock`. Container path: `Dockerfile.bench` /
`make docker-bench`.

---

## Classical ($0, offline, on `main`)

### RandomAgent — seeds `0`–`99`, canonical `seed=42`

| Item | Value |
|---|---|
| Seeds | `0..99` (`scripts/regime_lib.py`: `N_SEEDS = 100`) |
| Canonical single-seed draw | `seed=42` (`SEED42 = 42`) |
| Script | `scripts/run_random_n100.py` |
| Fixtures | `benchmark/prices/paper/` (PETR4, VALE3, ITUB4, BBDC4, `IDX_BVSP` for ^BVSP) |
| Summary (one row per regime×ticker) | `benchmark/results/random_n100/summary.csv` |
| Per-seed long table (20×100 rows) | `benchmark/results/random_n100/per_seed_returns.csv` |
| Paper table | `docs/paper_random_n100.tex` |

Downstream EW portfolios use the **N=100 mean** per ticker (not seed=42)
via `scripts/run_ew_portfolio.py` → `benchmark/results/baselines/` +
`docs/paper_ew_portfolio_baselines.tex`.

### `make reproduce` scope

Regenerates **only** these classical artifacts from committed Close
fixtures (no `.env`, no LLM, no download):

1. `scripts/run_random_n100.py` → `random_n100/*` + `docs/paper_random_n100.tex`
2. `scripts/run_ew_portfolio.py` → `baselines/*` + `docs/paper_ew_portfolio_baselines.tex`
3. `scripts/run_brazilbench.py --write` → `benchmark/results/brazilbench/matrix.csv` + `docs/brazilbench_baselines.md`

Pinned in CI by `tests/test_reproduce.py` (byte-identical regen). A clean
`git status` after `make reproduce` means the committed tables match.

**Not regenerated by `make reproduce`:** hand-typed classical tables /
figures inside `docs/brazilbench.tex` (earlier price vintage); any LLM
factorial results; open-branch artifacts listed below.

### Ollama vs Hugging Face (how to read model lines)

| Path | Serving | Typical ids in this repo |
|---|---|---|
| Local LLM logs / cold-start | **Ollama** tag (`model:size`) | `mistral:7b`, `qwen2.5:7b` |
| Chronos comparator | **HF** model id via `chronos-forecasting` | `amazon/chronos-t5-tiny` |
| Kronos analyst (pipeline) | HF / torch (GPU-oriented) | separate from `$0` `make reproduce` |

Do not treat an Ollama tag and an HF id as interchangeable.
